## Systemic notes

1. **"Verlauf" is overloaded.** It is the Gradient tool's short label and running-text word (toolGradientShort, ditherPageHint, acOverBody), the glossary's word for a palette ramp (paletteSortBody, acSummary), and, in replayNoHistory, "history". In a drawing app a German reader takes "Verlauf" as a gradient first. Recommendation: in running text write the gradient as "Farbverlauf" (the full tool name already is), keep "Verlauf" only where space forces it, and never use it for history. The glossary's ramp = "Verlauf" is tolerable because a ramp looks like a stepped gradient, but if it is revisited, "Farbabstufung" would remove the collision.
2. **One verb for merging layers.** The glossary allows "vereinen / zusammenführen", and the pack uses both for the same operation (layersMerge "Vereinen" vs layerMergeDown, layersMergeGap, layersMerged "zusammenführen"). A status message that names a button must use the button's word. Recommendation: "vereinen" everywhere (shorter, fits the one-word bar label, and is GIMP's German), and narrow the glossary entry to that one word.
3. **The same English, different German, and the reverse.** engineRefused / engineRefusedFallback translate one English sentence two ways; placeDroppedStorage / placeDroppedCanvas and cropCanvasTitle / importCrop collapse two different English texts into one German text, losing the distinction the English draws. Worth a mechanical pass: equal `en` should give equal `de` unless the context differs, and different `en` on the same screen should not give equal `de`.
4. **Direction words.** Movement needs "nach" (1 px nach oben), not the position word ("Oben 1 px"); see the four nudge tooltips. The Layers page already does this right ("Nach oben verschieben").
5. **Minor patterns, no change needed everywhere.** The editor's "artwork" (a local drawing) is rendered "Werk", the glossary's word for a published post; "Zeichnung" is more precise on the Artwork colors page, but it is not misleading. Menu ellipses consistently take a space ("Ebenen …"), which matches macOS German style; keep it consistent. Hints and errors use the infinitive ("Frame-Nummern eingeben"), which is normal German UI style; only mixing it with a du-imperative inside one message (palettesHint) reads oddly.
